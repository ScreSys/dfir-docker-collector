# DFIR Docker Collector

Nowadays more and more applications run in containers. They are fast to deploy, portable across environments and easy to scale. They also isolate applications from each other and from the host, so many organizations treat them as part of their security strategy.

For incident responders, the same features are a problem. A single host can run dozens of containers, often short-lived and built on minimal images with no tools inside. Entering each container one by one to collect evidence takes a lot of time, can alter the evidence itself, and the logs are often scattered between the container, its volumes and the host.

A single-file Bash script for the **forensic collection of Docker containers** (running, paused, restarting or stopped) on a Linux host running Docker Engine.

The target of the collection is the **containers**: their processes, network state, writable layer, files, logs and applications. The script also records the **host context a container investigation needs** (Docker events, daemon configuration and journal, runtime sockets, kernel state shared with the containers) and a set of host access records.

Everything it does is logged, and the result is a hashed, verifiable evidence set.

> **Use only on systems you are authorized to investigate.** The output contains sensitive data (see [Security and handling](#security-and-handling)).

## What it does

- Collects **volatile data** (processes, `/proc`, network tables) of **all** selected containers first, then the slower **static data** (writable layer, files, logs, applications).
- Handles **running, paused and restarting containers** (anything with a live PID) and **stopped containers** (static data only).
- Recovers **deleted and memfd executables** and open-but-deleted files from `/proc` (fileless malware, removed logs).
- Is **log-driver aware**: it detects each container's log driver, collects the logs accordingly, and raises an alert when logs are missing or stored off-host.
- Detects **well-known applications** inside each container (web servers, databases, app servers, brokers, CI, proxies, ...) and copies their logs and configuration.
- Captures Docker events and the daemon journal **before** touching any container, so they do not contain events generated by the collector.
- Logs every Docker and `nsenter` command with a UTC timestamp, so collector-generated events can be discounted during analysis.
- Produces a **SHA256 manifest** with relative paths, and can create a `.tar.gz` archive encrypted with [age](https://github.com/FiloSottile/age).
- Raises **triage alerts** for suspicious conditions (risky container configuration, deleted/memfd executables, hidden processes, missing logs, ...).

### Design principles

- **Container data is untrusted.** Usernames and home directories read from a container's `/etc/passwd` are sanitized before being used in output paths. Nothing is executed inside a container unless `--allow-exec` is given.
- **Minimal footprint.** A trusted `PATH` is enforced and `LD_PRELOAD` / `LD_LIBRARY_PATH` / `LD_AUDIT` are unset. Network tools run from the host inside the container's network namespace with `nsenter`. Files are read with `docker cp` or from the host side, never with `docker exec` by default.
- **Evidence integrity.** Timelines and archives use numeric UID/GID (`find %U/%G`, `tar --numeric-owner`, `docker cp -a`). The plaintext copy of a container's `/var/log` is deleted only after its archive has been written and listed back successfully. Cleanup only removes empty files and folders inside the tool's own `ERROR_LOG` folders.

## Requirements

**Mandatory**

| Requirement | Notes |
|---|---|
| Linux host with Docker Engine | The `docker` CLI must be available |
| Root privileges | Needed for `/proc/<PID>`, `nsenter` and Docker's data directory |
| Bash **4.4 or later** | Checked at start-up |
| GNU userland | GNU `date`, `find`, `du`, `stat`, `cp`, `tar`, `timeout`, `sha256sum`, `gzip` (BusyBox is **not** supported) |

**Optional** (used only if present; a missing tool is noted in the error log)

| Tool | Used for |
|---|---|
| `nsenter` | Running `ss`, `ip` and `lsof` inside each container's network namespace |
| `ss`, `ip`, `lsof` | Container and host network state |
| `journalctl` | Docker/containerd and kernel journal, `journald` container logs, host access activity |
| `iptables`, `ip6tables`, `nft` | Host firewall state (Docker's NAT and filter rules) |
| `ausearch` | Recent audit events |
| `last`, `lastb`, `utmpdump`, `lastlog` | Decoding host login records |
| `chronyc`, `ntpq`, `timedatectl` | Time synchronization state |
| `python3` | Only for `--dump-mem` |
| `age` | Only for encrypting the archive |

## Quick start

1. **Take a snapshot first**, if the host is a virtual machine or a cloud instance. The script runs on a live system and inevitably changes it (files written, access times, Docker events, page cache): a snapshot taken *before* copying the script preserves the original state, lets you image the disk later and gives you a fallback if something goes wrong. Prefer a snapshot that includes memory (VMware, Hyper-V, Proxmox, ...), which also preserves RAM; cloud disk snapshots (EBS, Azure managed disks, GCP persistent disks) preserve the disks only. Take it with the machine running: do not stop or reboot it, or the volatile data is lost.

2. Copy the script to the host and make it executable:

   ```bash
   chmod +x dfir-docker-collector.sh
   ```

3. Write the output to an **external or dedicated volume**, not to the disk under analysis. The volume should be formatted with a Linux filesystem (ext4, xfs): on exFAT/NTFS, ownership, permissions and symlinks of the copied files are lost.

### Interactive mode

```bash
sudo OUT_ROOT=/mnt/evidence ./dfir-docker-collector.sh
```

The script asks for a case ID, then shows a numbered table of every container on the host (running and stopped: ID, name, image, status, ports) and asks which ones to collect (all, all except some, or an explicit list) and a final confirmation. In the prompts you can use the row numbers from the table (`1,3`), names or IDs. It also asks before continuing when no destination is given (fallback to `/tmp`) or when free space is low.

### Non-interactive mode

```bash
# All containers, with archive
sudo ./dfir-docker-collector.sh --out /mnt/evidence --case-id IR-2026-042 --all --yes --archive

# Only some containers (names or IDs)
sudo ./dfir-docker-collector.sh --out /mnt/evidence --include web1,db1 --yes

# All containers except some
sudo ./dfir-docker-collector.sh --out /mnt/evidence --exclude monitoring --yes
```

### Encrypted archive

```bash
sudo AGE_RECIPIENT="age1xxxxxxxx..." ./dfir-docker-collector.sh \
    --out /mnt/evidence --all --yes --archive
```

### Help

```bash
./dfir-docker-collector.sh --help
```

## Command-line options

| Option | Description |
|---|---|
| `--out DIR` | Evidence destination (same as `OUT_ROOT`) |
| `--case-id ID` | Case or ticket number, recorded in the case metadata |
| `--all` | Collect all containers |
| `--include a,b` | Collect only these containers (names or IDs) |
| `--exclude a,b` | Collect all containers except these |
| `--yes`, `-y` | No prompts. Requires `--out` and one of `--all`, `--include`, `--exclude` |
| `--allow-exec` | Allow the `docker exec` fallback when `nsenter` or a host tool is missing. Every use is logged in `exec_window.log` |
| `--dump-mem` | Dump suspicious memory regions (rwx, anonymous executable, memfd). Requires `python3` |
| `--archive` | Create `<output>.tar.gz` (plus `.age` if `AGE_RECIPIENT` is set) |
| `--no-apps` | Skip the application log/config/web-content collection |
| `-h`, `--help` | Show usage |

Notes:

- `--include` takes precedence over `--all` and `--exclude`.
- With `--exclude`, if **none** of the excluded containers can be resolved, the script stops instead of silently collecting everything (exclusions are often legal or privacy constraints).
- Without `--out` / `OUT_ROOT` the script falls back to `/tmp` after a warning and a prompt; with `--yes` it refuses to run.
- In non-interactive mode there is no confirmation prompt: double-check the selection.

## Collection phases

| Phase | Scope | What happens |
|---|---|---|
| **Pre-checks** | Host | Root, Bash ≥ 4.4, GNU tools, Docker; free space; warning if the destination is `tmpfs` or on the same filesystem as Docker's data directory |
| **0. Setup** | Output | Creates the output folder (mode `700`), records case metadata, logs the whole console output to `collection.log` |
| **Selection** | – | Resolves names/IDs to full container IDs, prints a summary and asks for confirmation (unless `--yes`) |
| **1. Host context** | Host | Docker events (first), Docker configuration, firewall/network, kernel state, journals, audit, login records |
| **1b. Container logs** | Selected containers | Logs and config files read directly from Docker's data directory, according to the log driver |
| **2. Volatile** | All selected containers with a live PID | Processes, `/proc` data, recovery of deleted files, network state |
| **3. Static** | Each selected container | Docker metadata, risk flags, UpperDir, mount timelines, recent files, `/dev/shm`, files copied out, user artifacts, applications |
| **4. Cleanup** | Tool folders | Removes only empty files/folders inside the tool's own `ERROR_LOG` folders |
| **5. Integrity** | Output | SHA256 manifest of everything collected, then hash of the manifest |
| **6. Archive** *(optional)* | Output | `.tar.gz`, optionally encrypted with `age` |

## What is collected from each container

### Container logs (phase 1b)

The log driver is detected per container and recorded in `docker_container_files/log_driver.txt` together with its options.

| Driver | Behavior |
|---|---|
| `json-file` | Raw JSON logs (including rotated and compressed ones) are copied |
| `local` | The `local-logs/` folder is copied |
| `journald` | The container's entries are exported from the host journal (`CONTAINER_ID_FULL=<id>`) |
| `none` | **Alert**: the container has no logs |
| anything else (`syslog`, `gelf`, `fluentd`, `awslogs`, `splunk`, ...) | **Alert**: logs are **not** on this host; the destination is recorded and the dual-logging cache in `local-logs/` is copied if present |

`config.v2.json`, `hostconfig.json`, `hostname`, `hosts` and `resolv.conf` from Docker's data directory are copied too. Rotation options (`max-size` / `max-file`) are reported because they limit the available history.

### Volatile data (phase 2)

- **Process list from two independent sources**: `docker top` (cgroup) and a scan of host `/proc` for processes in the same PID namespace. A mismatch raises an alert.
- **Per process** (`proc/<PID>/`): `status`, `stat`, `statm`, `io`, `limits`, `cgroup`, `mounts`, `mountinfo`, `maps`, `smaps_rollup`, `comm`, `cmdline`, `environ`, `loginuid`, `uid_map`/`gid_map`, security context, `wchan`, `syscall`, `fd` and `fdinfo`, namespaces, thread names, `exe`/`cwd`/`root` links.
- **Triage table** `proc_summary.tsv`: PID, PPID, UID, effective capabilities, seccomp, no-new-privs, executable path, executable SHA256, command line.
- **Recovery** into `proc_recovered/`: deleted or memfd executables and open-but-deleted files, each hashed immediately and with an `.origin.txt` file describing the source.
- **Memory regions** (`--dump-mem`): rwx and anonymous/memfd executable regions, read-only through `/proc/<PID>/mem`, no `ptrace` attach.
- **Network**: `/proc/<PID>/net/*` tables (tcp, udp, unix, route, arp, ...), plus `ss`, `ip a`, `ip neigh`, `ip route`, `lsof -i` run with host binaries inside the container's network namespace. PIDs shown are host PIDs.

### Static data (phase 3)

- **Docker metadata**: `inspect`, `logs --timestamps` (stdout and stderr in one file), `diff`, `port`, `stats`, image history (build-time commands).
- **Risk flags** (`risk_flags.txt`): privileged mode, added and dropped capabilities, PID/IPC/network/user namespace modes, security options, devices, read-only rootfs, user. Mounts are listed in `mounts.txt`, and any reference to a container runtime socket is extracted.
- **Writable layer (UpperDir)**: a timeline of every file and a size-capped `upperdir.tar.gz` (xattrs and ACLs included, atime preserved). Not available with the containerd image store.
- **Volumes and bind mounts**: timeline of files modified or changed in the last `RECENT_DAYS` days, per mount.
- **Recent files**: files modified or changed in the last `RECENT_DAYS` days, as seen from the host through `/proc/<PID>/root` (live containers only).
- **`/dev/shm`**: copied from the host view, size-capped (live containers only).
- **Files copied with `docker cp`** (works on stopped containers too):
  - accounts: `/etc/passwd`, `shadow`, `group`, `sudoers`, `sudoers.d`
  - system: `hosts`, `resolv.conf`, `nsswitch.conf`, `os-release`, `ld.so.preload`, `ld.so.conf`, `ld.so.conf.d`, `profile`, `profile.d`, `environment`, `sshd_config`
  - packages: dpkg status, apk installed, rpm databases
  - scheduling: `/var/spool/cron`, `/etc/crontab`, `/etc/crontabs` (Alpine), `/etc/cron.d`, `cron.hourly/daily/weekly/monthly`
  - temporary and logs: `/tmp`, `/var/tmp`, and the **whole `/var/log`** of the container, stored as `var_log.tar.gz`
- **User artifacts** (`users_data/uid<N>_<name>/`), for every home directory in the container's `/etc/passwd`, plus `/root` if it is not listed: shell histories (bash, ash, zsh, sh), Python, MySQL and PostgreSQL histories, `.viminfo`, `.lesshst`, `.wget-hsts`, `.ssh`, trash.
- **Applications** (`apps/`, the last step): logs and configuration of detected well-known applications, then log-like files (`*.log`, `*.err`, `nohup.out`, ...) found in bind mounts and volumes, then web content (webroots, webapps), all under the per-container `MAX_APP_MB` cap. Application log folders under `/var/log` that are already inside `var_log.tar.gz` are not copied a second time and do not count toward the cap. Every path found is listed in `apps/apps_detected.tsv`, with status `COPIED`, `IN_VAR_LOG` (already in `var_log.tar.gz`) or `FAILED`.

  Recognized applications: nginx/OpenResty, Apache httpd, PHP/PHP-FPM, Tomcat, WildFly/JBoss, Keycloak, MySQL/MariaDB, PostgreSQL, SQL Server, MongoDB, Redis, Elasticsearch, Logstash, Kafka/ZooKeeper, RabbitMQ, HAProxy, Traefik, Caddy, Jenkins, GitLab, Grafana, Jira/Confluence, Supervisor, rsyslog, Gunicorn/uWSGI, PM2, and generic `/app/logs`-style folders.

  Database data files and secrets (Jenkins secrets, `gitlab-secrets.json`, `wp-config.php`, cloud credentials) are deliberately **not** collected; add the paths to `APP_TABLE` / `USER_FILES` in the script if the case requires them.

## Host context

The host is not the target of the collection, but a container investigation needs part of it. Phase 1 collects:

- **Docker**: events for `EVENTS_DAYS` days (with a check for truncated history), `docker info`, version, networks, volumes, images with digests, `ps -a`, default log driver, `daemon.json`, containerd config, Docker systemd units and drop-ins, `docker` group members, permissions of the Docker and containerd sockets.
- **Journal**: Docker and containerd units, kernel messages.
- **Network and firewall**: `iptables` (filter and nat), `ip6tables`, `nft` ruleset, addresses, routes, sockets, process tree, kernel modules.
- **Kernel state shared with containers**: version, cmdline, taint flags, `core_pattern`, `modprobe`, `ptrace_scope`, unprivileged BPF, user namespaces, `binfmt_misc`, `dmesg`.
- **Time synchronization**: `timedatectl`, `chronyc`, `ntpq`.
- **Host access records**: `last`, `who`, `lastlog`; raw and decoded `wtmp*`, `btmp*`, `lastlog`, `faillog`, `utmp`; journal export of sshd (including `sshd-session` / `sshd-auth`), sudo, su, login, cron/atd, logind and account tools for `ACCESS_DAYS` days; journal coverage checks.
- **Raw host logs** (each capped at `MAX_HOSTLOG_MB`): `/var/log/audit`, the current `auth.log` and `auth.log.1`, `secure*`, the current `syslog` and `messages`.
- **Host files**: `/etc/ld.so.preload`, `/etc/crontab`, `/etc/cron.d`, `sshd_config`, root's `authorized_keys`.

This is **not** a full host collection: rotated host logs, other users' SSH keys, systemd units and timers, and other host persistence locations are not collected. Use a dedicated host collector if a container escape is suspected.

## Output layout

Everything is written to `<OUT_ROOT>/dfir_containers_<UTC timestamp>/`:

```
dfir_containers_YYYYMMDDTHHMMSSZ/
├── case_metadata.txt          # case ID, examiner, script path and SHA256, versions, options, selected containers
├── README_formats.txt         # file formats and verification steps
├── collection.log             # full console output
├── collection_errors.log      # notes, skipped items and coverage problems: READ IT
├── actions.log                # every docker / nsenter command with UTC timestamp
├── exec_window.log            # only if the docker exec fallback was used
├── triage_alerts.txt          # alerts raised during the run
├── SHA256SUMS.txt             # hash manifest (relative paths)
├── SHA256SUMS.txt.sha256      # hash of the manifest
├── ERROR_LOG/                 # stderr of host-phase commands (empty files removed)
├── HOST_ARTIFACTS/
│   ├── docker_*.txt, host_*.txt, journal_*.export / .txt, decoded_*.txt
│   ├── etc/, root/            # host files, kept under their original path
│   ├── proc_host/             # selected host /proc values
│   └── raw_logs/              # raw audit, auth, wtmp/btmp, ...
└── containers/
    └── <container name>/
        ├── docker_container_files/        # logs and config from Docker's data dir, log_driver.txt
        ├── docker_inspect.json, docker_logs_combined.txt, docker_diff.txt, docker_port.txt, docker_stats.txt
        ├── risk_flags.txt, mounts.txt, flag_runtime_socket_mount.txt, image_history.txt
        ├── upperdir_timeline.tsv, upperdir.tar.gz
        ├── mounts_timeline/, recent_files_modified_<N>_days.tsv, dev_shm/
        ├── ps_host_view.txt, docker_top.txt, pids_docker_top.txt, pids_ns_scan.txt, pids_mismatch.txt, pids_all.txt
        ├── proc/<PID>/, proc_summary.tsv, proc_net/, proc_recovered/
        ├── ss.txt, network_ip.txt, network_arp.txt, network_route.txt, lsof_net.txt
        ├── passwd, shadow, group, ..., var_log.tar.gz
        ├── users_data/uid<N>_<name>/, users_data/uid0_root_fallback/
        ├── apps/<app>/, apps/volume_logs/, apps/apps_detected.tsv
        └── ERROR_LOG/
```

### Timeline format

`upperdir_timeline.tsv`, `mounts_timeline/*.tsv` and `recent_files_*.tsv` are tab-separated and sorted newest first:

```
mtime  ctime  uid  gid  type(f/d/l/...)  size  /path
```

- **Timestamps are in the host's local time zone, without an offset** (unlike the logs of the tool, which are UTC). Read the host time zone in `case_metadata.txt` ("Timestamp local") and `HOST_ARTIFACTS/host_timedatectl.txt` before correlating, or run the script with `sudo TZ=UTC ./dfir-docker-collector.sh ...` to get UTC timelines.
- UID/GID are numeric on purpose: never resolve them with the host's `passwd`.
- File names containing tabs or newlines can break parsers.
- A `# TRUNCATED` line at the end means `find` hit `TIMEOUT`.

## Triage alerts

Alerts are printed, logged and saved in `triage_alerts.txt`:

| Alert | Meaning |
|---|---|
| PID mismatch | `docker top` and the PID-namespace scan disagree (hidden or escaped processes?) |
| Deleted/memfd executable | A process runs a binary that no longer exists on disk |
| Runtime socket | `docker.sock`, `containerd.sock`, ... referenced in the container configuration (full host control) |
| Risky runtime configuration | Privileged, host PID/IPC/network, unconfined profiles, or capabilities such as `ALL`, `SYS_ADMIN`, `SYS_PTRACE`, `SYS_MODULE`, `DAC_READ_SEARCH`, `NET_ADMIN`, `NET_RAW` |
| Sensitive bind mount | Exactly `/`, `/etc`, `/root`, `/proc`, `/sys`, `/var/run`, `/run`, `/var/lib/docker` or `/home` bind-mounted |
| No logs / off-host logs | Log driver `none`, or a remote driver |
| Tainted kernel | Out-of-tree or unsigned kernel modules on the host |
| Volatile journal | The journal lives only in `/run/log/journal` and is lost at reboot |

Coverage problems (truncated Docker events, journal shorter than the requested window, empty `wtmp`/`btmp`, size caps, low disk space, `find` timeouts, processes that exited during the run) are written to `collection_errors.log`. **Read it before drawing conclusions from missing data.**

## Integrity, archive and encryption

At the end of the run the script prints the SHA256 of the manifest:

```
SHA256 of SHA256SUMS.txt (record it OUT OF BAND in the ticket):
  <hash>
```

Record it in your case notes, outside the evidence folder. To verify the evidence later:

```bash
cd /mnt/evidence/dfir_containers_<timestamp>
sha256sum -c SHA256SUMS.txt
sha256sum -c SHA256SUMS.txt.sha256
```

Symlinks copied from containers are not files and are therefore not listed in the manifest.

With `--archive` the script creates `<output>.tar.gz` and its `.sha256`. If `AGE_RECIPIENT` is set and `age` is installed, it also creates `<output>.tar.gz.age` and its `.sha256`. The plaintext folder and the unencrypted `.tar.gz` are **not** removed: delete them securely once the `.age` file is in its final location. The archive needs as much free space as the evidence folder (twice as much with encryption).

## Security and handling

The output **contains sensitive material**:

- `/etc/shadow`, `sudoers` and `.ssh` folders copied from containers;
- process environments (`environ`), which often hold secrets and tokens;
- shell histories, application configuration and web content;
- optional memory dumps;
- files copied from compromised containers: possible malware, setuid files and device nodes.

Recommendations:

- Store the output on an **encrypted, access-controlled volume**, ideally mounted `nosuid,nodev,noexec`. The script sets `umask 077` and mode `700` on the output folder.
- Do not write the output to a path that is bind-mounted into any container: the container could read or alter the evidence while it is being collected.
- Use `--archive` with `AGE_RECIPIENT` to move the evidence between systems.
- Run the script with `sudo` from your own user so the real examiner (`$SUDO_USER`) is recorded in the case metadata.
- Check legal and privacy constraints before collecting; use `--exclude` for containers that must not be acquired.
- The script uses the host's binaries. If the host itself may be compromised, set `TRUSTED_PATH` to a trusted static toolkit.

## Limitations

- **Docker Engine on Linux only**, GNU userland required. Rootless Docker, Podman and containers started directly with containerd (`ctr`, `nerdctl`) are not collected.
- A **triage and acquisition tool**, not an analysis tool, and not a forensic image of the host or of the containers.
- Collection runs on a **live system**: volatile data is a snapshot and processes may exit during the run (noted in the error log).
- With the **containerd image store** the UpperDir path is not exposed by `docker inspect`: no UpperDir timeline or archive. `docker diff`, `docker cp` and the application collection still work.
- The Docker daemon keeps only a **small in-memory event buffer**: on busy hosts the events cover far less than `EVENTS_DAYS`. The script reports when it suspects truncation.
- `docker cp` copies **symlinks as symlinks**. For example, in the official nginx image `/var/log/nginx/access.log` is a link to `/dev/stdout`: the logs are in the container log, not in the file.
- Size caps (`MAX_*`) and `SPACE_FLOOR_MB` can cause data to be skipped; every skip is noted.
- If `nsenter` or the host network tools are missing, container network output is skipped unless `--allow-exec` is used. `--allow-exec` runs commands **inside** the container and generates events there; it is traced in `exec_window.log`.
- No handling of interruptions: if the run is stopped (Ctrl-C), no manifest is generated.

## Troubleshooting

| Problem | Solution |
|---|---|
| `bad interpreter` or odd syntax errors | Windows line endings: `sed -i 's/\r$//' dfir-docker-collector.sh` |
| `ERROR: run as root` | Run with `sudo` |
| `ERROR: bash >= 4.4 required` | Upgrade Bash on the host |
| `ERROR: GNU date/find required (not BusyBox)` | Run on a standard GNU/Linux host |
| `ERROR: stdin is not a terminal` | Use `--yes` with `--out` and `--all`, `--include` or `--exclude` |
| `ERROR: --yes requires a selection` | Add `--all`, `--include` or `--exclude` |
| `ERROR: with --yes an explicit --out is mandatory` | Pass `--out /path/to/evidence` |
| `ERROR: not enough space in non-interactive mode` | Free space on the destination or lower `MIN_FREE_MB` |
| `ERROR: none of the excluded containers was found` | Check the names/IDs passed to `--exclude` (`docker ps -a`) |
| `WARNING: OUT_ROOT is on the same filesystem as ...` | Use an external or dedicated volume for `--out` |
| `UpperDir not available` in the error log | Containerd image store or a non-overlay storage driver: see [Limitations](#limitations) |
| Many "SKIPPED" entries in `collection_errors.log` | Check free space and the `MAX_*` / `SPACE_FLOOR_MB` limits |
